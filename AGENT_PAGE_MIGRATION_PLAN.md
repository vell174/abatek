# План агента: перенос страниц по одной

## Цель

Последовательно переносить страницы с `abatek.ru` в проект АБАТЭК. За одну итерацию агент обрабатывает только одну страницу и не переходит к следующей, пока текущая не проверена.

## Источники

- Список URL: `ABATEK_UNIQUE_LINKS_NO_CITIES.md`.
- Приоритетный локальный источник: `abatek-copy3`. HTML страницы брать из `abatek-copy3/<slug>/index.html` или `abatek-copy3/<slug>.html`, оригинальные изображения — из `abatek-copy3/img`. Не обращаться к живому `abatek.ru`, если нужные HTML и файлы присутствуют в локальной копии.
- Исходная страница: URL из списка.
- Локальная архитектура: `app/data/pages`, `app/components/equipment`, `app/pages/[slug].vue`.
- Оригинальные изображения: брать с исходной страницы или из её HTML, сохранять в `public/images`.

## Правила переноса

1. Взять первую ещё не обработанную ссылку из `ABATEK_UNIQUE_LINKS_NO_CITIES.md`.
2. Открыть исходную страницу и выписать только её содержательные блоки:
   - заголовок, описание и CTA;
   - характеристики и параметры;
   - виды оборудования и комплектации;
   - области применения;
   - этапы производства;
   - FAQ;
   - контактные данные, если они уникальны для страницы.
   - Никаких сокращений: переносить всю содержательную информацию, технические характеристики, таблицы, виды оборудования и все тематические изображения исходной страницы. Допустима только редактура орфографии и структуры без потери данных.
   - Жёсткое правило завершения: страницу нельзя помечать готовой и нельзя переходить к следующему URL, пока по чек-листу не подтверждены все содержательные блоки, все таблицы, все тематические изображения и все отдельные товарные позиции исходной страницы. Если шаблон не поддерживает элемент, сначала расширить шаблон.
   - Все таблицы исходной страницы переносить через shared-компонент `SpecsTableSection`: сохранять заголовок, названия колонок, порядок строк и все значения без сокращений. Самописную таблицу в странице не использовать.
3. Не переносить навигацию, дублирующиеся формы, политику конфиденциальности и служебную разметку исходного сайта.
4. Не создавать геостраницы и не добавлять города в URL, title или отдельные карточки.
5. Блоки «Выполненные проекты» переносить только по отдельному указанию пользователя. По умолчанию исключать.
6. Изображения не заменять заглушками:
   - найти реальные URL изображений на исходной странице;
   - скачать оригиналы в `public/images` с понятными именами;
   - проверить, что все пути в данных существуют.
7. Использовать существующий шаблон страницы оборудования, если он подходит:
   - `IndustrialEquipmentPage` для стандартных страниц;
   - `ScraperProductCard` для каталогов с карточками товаров;
   - `ContactWorkflow` для стандартной схемы работы;
   - `FaqSection_last_01` для FAQ;
   - не создавать новый компонент, если уже есть подходящий shared-компонент.
8. Для нового оборудования добавить:
   - `app/data/pages/<slug>/name-routers.ts`;
   - `app/data/pages/<slug>/data.ts`;
   - `app/data/pages/<slug>/seo.ts`;
   - запись `<slug>` в `specialTemplates` в `app/data/pages/index.ts`.
9. Для каталога использовать `ScraperProductCard`, если страница содержит отдельные модели/виды с изображениями.
10. Тексты аккуратно отредактировать: убрать явные ошибки исходника, сохранить фактический смысл и технические характеристики, не придумывать неподтверждённые параметры.
11. Акцент на SEO

## Порядок работы одной итерации

### 1. Анализ

- открыть URL;
- определить тип страницы и подходящий локальный шаблон;
- собрать список блоков и изображения;
- проверить, нет ли уже такого маршрута в проекте.

### 2. Реализация

- создать или обновить data/SEO/route-файлы;
- подключить маршрут в `app/data/pages/index.ts`;
- добавить оригинальные изображения;
- подключить каталог, FAQ и этапы из shared-компонентов;
- исключить проекты и геоблоки по правилам выше.

### 3. Проверка

- проверить существование всех изображений;
- убедиться, что URL страницы уникален;
- убедиться, что в данных нет городских URL и геотекстов;
- выполнить `npm run lint`;
- выполнить `npx nuxi typecheck`;
- при необходимости выполнить `npm run generate` или сборку;
- записать результат и найденные ограничения.

### 4. Завершение итерации

- отметить обработанную ссылку в рабочем журнале агента;
- сообщить пользователю: URL, созданные файлы, количество изображений и результаты проверок;
- только после этого брать следующую ссылку.

## Критерии готовности страницы

- Страница открывается по ожидаемому URL.
- Используются реальные изображения исходной страницы.
- Нет блока проектов, если он не разрешён отдельно.
- Нет городских страниц и дублей.
- Каталог использует подходящий shared-компонент.
- `npm run lint` и `npx nuxi typecheck` завершаются без ошибок.

## Повторная сверка

18.08.2026 повторно проверены все 57 страниц по локальным HTML: содержательные блоки, таблицы, товарные позиции и тематические изображения соответствуют источникам. Для `/rgs-10/`, `/rgs-100/`, `/rgs-120/` и `/rgs-15/` отсутствовавшие HTML сохранены в `abatek-copy3`; связанные изображения уже находились в `abatek-copy3/img`.

По структуре локальных HTML добавлены два shared-шаблона: `ConveyorApplicationPage` для 23 отраслевых страниц и `ReservoirModelPage` для 14 моделей РГС. Остальные страницы типов оборудования и комплектующих используют `IndustrialEquipmentPage`.

Header приведён к структуре каталога из `abatek-copy3`: все 57 перенесённых страниц добавлены в desktop- и mobile-меню без дублей, а блок «Категории» на главной переименован в «Каталог».

В `ScraperProductCard` добавлена опциональная ссылка на отдельную страницу товара. Ссылки назначаются только карточкам, для которых соответствующий HTML подтверждён в `abatek-copy3`.

Для 60 страниц созданы `gallery.ts` с изображениями только из секции «Выполненные проекты» локального HTML. Оригиналы сохранены в `public/images/gallery`; страницы без такой секции имеют пустой массив.
